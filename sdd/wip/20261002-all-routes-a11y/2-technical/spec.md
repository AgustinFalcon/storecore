# Test architecture

e2e/route-manifest.ts owns readonly Screen records and the closed ScreenRealm enum. The 24 patterns include concrete synthetic parameter URLs, expected heading and readiness selector.
e2e/runtime-routes.ts parses app.routes.ts using the existing TypeScript dependency, without importing/bootstrapping Angular; unsupported route topology fails rather than silently excluding entries. The browser suite compares exact sorted patterns and uniqueness, not just a count.
e2e/api-fixtures.ts intercepts requests through page.route before navigation. Public/CUSTOMER/USER fixture maps preserve BaseResponse and CSRF contracts. The opposite realm's session probe returns an expected 401; only the selected realm gets authenticated. Unknown API GETs and all writes are aborted and recorded; external origins are aborted. No production fixture binding or auth bypass is added.
Playwright gives every test a fresh browser context. Synthetic sessionStorage seeds the existing favorites prototype only. Populated cart, order, catalog, address, offer, promo, inventory and ML listing fixtures exercise conditional content. No button submits a write, payment or integration.
The same test:a11y job defines 24 smoke+axe cases, one manifest reconciliation check and eight focused fixture/parser/readiness regressions on Chromium desktop. It retains traces/report on failure, uses two CI workers and no retries. It is not screenshot/pixel comparison. Empty/error/loading/retry matrices and mobile remain later cuts.

Review corrections: the API handler enforces the exact preview origin before selecting any response (it precedes the catch-all in Playwright dispatch). Foreign origin/protocol/port and unknown API/write cases have focused handler tests; realm authentication is checked separately. Profile readiness asserts first name, last name and email values; content readiness asserts fetched title/body and published block text. Removing their loadProfile/loadHome calls therefore leaves empty defaults and fails smoke, even if session probes succeeded. Other data routes already require generated list rows, product headings, carousel content or fetched address options rather than empty forms.

The parser treats component routes with children:[] as leaves. It rejects loadChildren/loadComponent, non-array children and spreads instead of silently excluding unclassified topology. Regression tests exercise those cases. The readiness helper has two focused browser regressions demonstrating rejection of attached empty/default forms and of content without published blocks.
