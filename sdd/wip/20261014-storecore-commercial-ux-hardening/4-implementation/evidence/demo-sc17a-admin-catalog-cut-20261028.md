## AC y límites

- Feature dedicada, tipos cerrados/borde único, pasos puros Authorize → Query → Project → Validate → Save/SetPublication. Admin+Operator sólo SC17A, sin ampliar otros editores/operaciones. Módulo Catalog exige exactamente un registro enabled===true. Misma autoridad revalidada dentro de state.run con epoch y fingerprint del producto, no sólo en botón.
- Listado profesional con imagen SVG automática identificada Demo (no media editable), nombre/SKU/marca/categoría; publicación y stock separados; precio base/lista/actual con fuente. Búsqueda normalizada; filtros cerrados publicación/disponibilidad, facets existentes, paginación estable y URL/back/reload. Empty global distinto de filtered/no-results; Unknown query recuperable y datos ilegibles sin fallback seed.
- Editor create desde valores vacíos limpios, SKU único y estable; edit SKU inmutable, stock/reservas readonly. Create stock inicial cero explícito (ajuste SC22 separado). Precio entero seguro en minor units, original>=base antes de promociones; vigente es derivado, nunca persistido como base. Validación compartida por comando y decoder.
- Desactivar Case bloqueado si cualquier carrito/reserva activa depende de esa presentación; históricos siempre conservados. No rich variant model ni nuevo media field inventado. Cambios editor/publicación no alteran stock, movimientos, pedidos, aftercare, carritos, listings ni syncJobs; no queueStock por editar metadata.
- Publicar/archivar es comando target explícito, idempotente, no toggle. Publicar agotado es válido; archivar bloquea reservas. Fingerprint evita overwrite de metadata/stock stale, CAS/rollback/write-readback existente conserva borrador y no anuncia éxito antes de persistencia.
- Native dialog con revisión de efecto/cancelación, descarte explícito si dirty, Escape/foco/restauración y guard al navegar. Errors asociados a campo + foco, guardado fallido conserva draft. Logout/actor/epoch/destrucción invalidan modal y callbacks. No comandos a proveedor/ML ni backend/schema nuevo.
- Responsive 320/390/768/900/1440 y 200% text resize real, teclado/Axe, dinero indivisible sin overflow; CTA por producto verificadas y todos los filtros/pager probados. No claim de operaciones reales ni homologación.

## Implementación y checkpoints

`demo/admin-catalog` separa publicación/disponibilidad/filtros/diálogos/issues, política escalar compartida, criterios URL, pasos de proyección/filtro/paginación y comandos. La ruta dedicada aplica guard de descarte. El bloque antiguo de SC17 y su formulario se retiran del monolito sin cambiar Inventario. El shortcut de productos SC15 se habilita a Operator porque ahora ese destino sí está autorizado; no se amplían inventario/ML/configuración/ofertas.

`CatalogProductPolicy` se invoca por decoder y comandos; publicación flat exige boolean estricto (un wire string no equivale al boolean), supportsCase default histórico true sólo si falta/undefined y se normaliza ANTES de validar suma Case. Null/string/número explícitos no se reparan. La validación usa extraUnit del tipo cerrado existente, no un precio duplicado. `DemoCommerce.saveProduct` conserva su compatibilidad pero ya no llama queueStock por edición de metadata; SC17A usa comandos enfocados con fingerprint/actor/epoch. El modo nuevo parte de valores vacíos y cero stock, sin clonar el producto previo.

Guardado fuera de filtros o página actual: el aviso detecta la página visible, y «Ver producto guardado» limpia criterios, calcula página por SKU y enfoca esa fila. Preview local conserva búsqueda/página; archivado no ofrece enlace de compra. Nuevo/editar/publicación/preview/descarte usan dialog nativo, foco y teclado; navegación desde editor pide una decisión sin perder datos. Logout/actor/epoch/destrucción bloquean guardado incluso antes del efecto de limpieza.
