## Implementation review

### V11 SQL structure

- **Singleton:** `blackstore_catalog_revision` with `id=1 CHECK`, `revision>0`, seed `(1,1)`, owner `storecore_catalog_revision_owner`.  
- **Writer triggers:** `BEFORE INSERT OR UPDATE OR DELETE` on all six static tables named in slices/proposal: `products`, `product_variants`, `product_images`, `offers`, `offer_products`, `installation_settings`.  
- **Bump function:** `UPDATE … SET revision=revision+1, updated_at=clock_timestamp() WHERE id=1`; `NOT FOUND` → `BLACKSTORE_CATALOG_REVISION_MISSING`; correct `RETURN OLD`/`NEW` on DELETE.  
- **Share function:** exposes revision under definer ownership so runtime need not hold table `UPDATE` (PG `FOR SHARE` requires row lock compatible with concurrent static writers).  
- **Audit port:** whitelist `BLACKSTORE_PRICE_OVERRIDE` \| `BLACKSTORE_CATALOG_SKU_EXCLUDED`; JSON object payload; rejects `bearer`/`secret`/`secret_ref`; inserts into `audit_events` with correlation/reason columns.  
- **ACL:** no `GRANT ALL` to `storecore_runtime`; migrator `GRANT ALL` on singleton follows V8–V10 pattern; audit override `REVOKE ALL` from `PUBLIC`, `storecore_companion_admin`, `storecore_capability_admin`.
