## Required change

The empty sentence is false for the user-content payload that exists today.

`adminHomeDraft()` returns `HomeDraft(title, body)`. The integration test asserts `title` and `body` only. Public `GET /content/home` is the response that already builds `blocks` from active `home_content_sections`. This PR correctly does not call that public route and does not add an endpoint.

After a successful operator GET, `blocks` is omitted, `homeBlocks` becomes `null`, and the template prints “Este home no tiene bloques para el banner.” That sentence says the home has no banner blocks. The user-content body does not say that. The same sentence also appears when the GET fails or the title validation fails, because those paths set `loading: false` and leave `homeBlocks` at its initial `null`. The store’s first emission is the same pair (`loading: false`, `homeBlocks: null`) before `loadHome` flips `loading`.

An explicit `blocks: []` does not use that sentence; it renders an empty list. The claim is wired to a missing field, not to an empty array.

Required before this lane can approve:

- List `title` and `body` only when the user-content payload includes a `blocks` array.
- When `blocks` is omitted, render no sentence that the home has no banner blocks.
- Do not render that sentence on an error, on “El título es obligatorio.”, or before a successful load.
- Keep the save body as title and body only.
