## Required change

That sentence is gone.

`7572278` deletes it and wraps the list in `@if (state.homeBlocks)`. A search of `7572278` for that sentence under `*.html`, `*.ts`, and `*.kt` finds no match. The worktree template matches that commit: title and body fields, then the banner section only inside that `@if`.

| Case | Code |
| --- | --- |
| GET omits `blocks` | `mapHomeDraft` returns title and body only when `blocks` is not an array. `loadHome` sets `homeBlocks` to `home.blocks ?? null`. `@if (state.homeBlocks)` is false for `null`, so the section is absent. `adminHomeDraft()` still returns `HomeDraft(title, body)`, so today’s operator GET is this case. |
| GET returns a `blocks` array | The section lists each `block.title` and `block.body`. There are no inputs. |
| Error on load or save | Those handlers set `loading` and `errorMessage` and do not assign `homeBlocks`. They do not print an empty-banner sentence. |
| Title validation | `persistHome` sets “El título es obligatorio.” and does not touch `homeBlocks`. |
| Before load | Initial state is `loading: false` and `homeBlocks: null`. The first paint has no empty-banner sentence. |
| Save | `persistHome` executes `{ title, body }`. `homeDraftSavePayload` returns only those two fields. `PUT /user/content/home` sends that object. `setHome` and the view `patch` keep the editable draft to title and body. A PUT response that omits `blocks` leaves `homeBlocks` as it was. |

An explicit empty array is still an array, so the heading and an empty `<ul>` can show. That does not say the home has no banner blocks.
