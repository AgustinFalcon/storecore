## Empty-banner sentence

The sentence is honest. It is a claim about the latest successful public `blocks` array, and only when that array is empty.

The template prints it only inside `@if (!state.loading && !state.errorMessage && state.homeBlocks)` when `length === 0`. `homeBlocks` is filled from `published.blocks` of `GetHomeUseCase`, on load and again after a successful publish. Live `home()` always serializes `blocks`. Length 0 means no active home sections. The storefront carousel is that same list (`slice(0, 5)`), so an empty array is a real empty banner. Listing `title` and `body` happens only in the other branch, when that array has rows.

| Case | `a2970dc` |
| --- | --- |
| Console GET omits `blocks` | `loadHome` copies only `draft.title` and `draft.body` into the form. The list comes from the public read. Omission does not become `[]` and does not print the sentence by itself. |
| Public load returns `blocks: []` | The sentence shows. That public list is empty. |
| Public load returns rows | The section lists each mapped `title` and `body`. No inputs and no invented slides. |
| Load fails | `forkJoin` errors, `homeBlocks` is `null`, `errorMessage` is set. The sentence is hidden. |
| Title validation | Sets “El título es obligatorio.” and does not assign `homeBlocks`. `errorMessage` hides the section. |
| Before a successful load | Initial `homeBlocks` is `null`. No sentence. A reload sets `loading: true`, which hides the section. |
| Successful publish | `persistHome` sends `{ title, body }`, then calls `publicHome.execute()` again and replaces `homeBlocks` with that new `published.blocks`. While the save and the re-read are in flight, `loading` hides the section. The pre-save `[]` is not painted after the hero insert. |
| Public re-read fails after save | `homeBlocks` is set to `null` and `errorMessage` is set. The sentence is hidden. The form keeps the saved title and body. |
| Save request fails | `errorMessage` is set. The section stays hidden. `homeBlocks` is not copied from the console draft. |

`saveHome` still inserts an active `hero` when that row is missing. The conflict update does not set `active`. A home that already has an inactive hero and no other active sections can still read back `[]`. The sentence then matches that public read. It is not the old claim that a missing console field means the banner is empty.

`mapHome` still turns a missing or non-array `blocks` field into `[]` through `items()`. This commit does not change `mapHome`. Live `home()` always includes the array. A public payload that omitted `blocks` would be misread as empty; that is not what this backend returns.
