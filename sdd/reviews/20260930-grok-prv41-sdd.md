## Release and expiry are now separate rows

Both new tests activate `MARKETPLACE_ML` with the same fixture the commit row already uses (`state='ACTIVE'` on the installation default), reserve one unit, then exercise the public engine method. `finally` restores `DISABLED`, so the existing “commit without ML” row still sees the default.

`release` calls `mutateReserved(..., already = "RELEASED")`. `expireDue` selects `state='RESERVED' AND expires_at <= now()` and calls `mutateReserved(..., already = "EXPIRED")`, which uses the same `releaseStock` body with saga state `EXPIRED`. The test forces that predicate by setting `expires_at` one second in the past, then expects `expireDue(100) == 1` and receipt state `EXPIRED`.

Inside the existing saga transaction, after the stock body, `emit` from `lockVariants` calls `projectionBridge.requestProjection(variantIds, projectionCause(already))`. `projectionCause` maps `RELEASED` and `EXPIRED` to `ProjectionSourceCause.ExternalBlackStoreRelease` and `ExternalBlackStoreExpiry`. Those wires are `EXTERNAL_BLACKSTORE_RELEASE` and `EXTERNAL_BLACKSTORE_EXPIRY`. The bridge delegates to the local projector and does not insert `LISTING_STOCK`. The outbox adapter inserts `STOCK_DESIRED_CHANGED` and a delivery row at `PENDING`.

Each new test asserts, on its own listing:

- saga state `RELEASED` or `EXPIRED`
- `desiredChangedCount == 1` (`kind = STOCK_DESIRED_CHANGED`)
- that row’s delivery status is `OutboxDeliveryStatus.Pending`
- `channel_listing_stock_projection.source_cause` equals the closed cause wire
- the historic `LISTING_STOCK` id is still that kind, and `to_jsonb(o)::text` is unchanged

Replay: a second `release` hits `if (row.state == already) return` before the bridge, and the count stays 1. A second `expireDue(100)` returns 0 because the row is no longer `RESERVED`, and the count stays 1. That is the worker replay. The same early return covers a second `mutateReserved` once the state is already `EXPIRED`.
