## Apply path

`FulfillmentCommand` accepts a request only when it equals `FulfillmentNextAction` for that order and stored state. `PaidStockReview` still yields no hint, so `PACKED` and `RECEIVED` on that order still fail. Unknown request wires (`IN_TRANSIT`, `RESTOCKED`) and skips (`PENDING` → `DELIVERED`, no return → `ADJUSTED`) fail the same equality check.

Accepted mappings:

- `PACKED` → `ShipmentStatus.Preparing` (`PREPARING`)
- `SHIPPED` → `ShipmentStatus.Shipped` (`SHIPPED`)
- `DELIVERED` → `ShipmentStatus.Delivered` (`DELIVERED`)
- `RECEIVED` → `RmaStatus.ReturnReceived` (`RETURN_RECEIVED`)
- `INSPECTED` → `RmaStatus.Inspected` (`INSPECTED`)
- `ADJUSTED` → `RmaStatus.Closed` (`CLOSED`)

`JdbcOrderService.ship` and `rma` call the typed overloads after one `fromWire` each. They throw `FulfillmentRejected` when the command returns null. Shipped and delivered timestamps still follow the stored status: `shipped_at` on `Shipped` or `Delivered`, `delivered_at` only on `Delivered`. A new shipment row still starts at `PENDING`. A new return still starts at `RETURN_RECEIVED`. Inspect still writes `inspection_result='RESTOCK'`. Close still restocks, then sets `CLOSED`. Fulfillment events still record the stored status wire.

`FulfillmentCommandTest` covers the three ship maps, the three RMA maps, skip, unknown, cancelled shipment, `PAID_STOCK_REVIEW`, and `REQUESTED`.
