## Implementation review

`FulfillmentCommand` is a domain object. The string overloads are the wire edge: one `fromWire` / `fromOptionalWire` each, then the typed methods. `JdbcOrderService.ship` and `rma` call the typed methods after a single `fromWire`, so POST uses `ShipmentTransition` and `RmaTransition`, the same types `FulfillmentNextAction` returns.

The sealed `when` maps only the three known transitions onto the stored statuses. `Unknown` is an explicit null. Persistence writes `stored.wire` (`PREPARING` / `SHIPPED` / `DELIVERED`, `INSPECTED` / `CLOSED`, and `RmaStatus.ReturnReceived.wire` on insert). Shipment timestamps still set `shipped_at` for shipped and delivered, and `delivered_at` only for delivered. RMA still creates on first receive, updates inspection with `RESTOCK`, and restocks only on close. `FulfillmentNextAction` comment now points POST apply at `FulfillmentCommand`; the hint wires are unchanged.

`FulfillmentCommandTest` covers the three stored mappings, skip, unknown request wires (`IN_TRANSIT`, `RESTOCKED`), `PAID_STOCK_REVIEW`, cancelled shipment, and `REQUESTED` RMA.
