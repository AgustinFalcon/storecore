## Implementation against the SDD why

The worker accreditation update writes `PaymentStatus.Approved.wire`, then `OrderStatus.Paid.wire` or `OrderStatus.PaidStockReview.wire`. Unpaid termination writes `PaymentStatus.forUnpaidTermination(effect).wire` and guards the row with `PaymentStatus.Pending.wire`. The order update writes `OrderStatus.Cancelled.wire` only while the row is `OrderStatus.PendingPayment.wire`. `apply` still sends only `REJECT` and `CANCEL` into that function; `UNKNOWN` still quarantines. `forUnpaidTermination` keeps the previous split: `REJECT` becomes `Rejected`, and every other effect becomes `Cancelled`. The commercial transition strings stay `PAYMENT_REJECTED` and `PAYMENT_CANCELLED` because they interpolate `paymentStatus.wire`.

`reverse` still records a reversal case and does not update `payments.status`. Official transaction rows still store the provider status string on `mp_order_payment_transactions`. Those columns are outside the local payment/order status writes this PR closes.
