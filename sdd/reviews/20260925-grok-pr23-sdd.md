## Claims that stay inside the code

The 20% assertions call `JdbcCatalogService` directly. They do not add the SKU to the cart. `CommerceHttpIntegrationTest` still adds a base-priced SKU and checks that `originalUnitPrice` and `effectiveUnitPrice` are present. Shared cart math is the port in `price`, not a second 80/100 cart assertion. The body describes the 20% case as the catalog scenario the new test covers.

“Cannot drift” is the shared formula at add or update. Checkout keeps the snapshot already on the line. An offer that ends after the line was stored does not rewrite that line. That is the existing TASK-006 snapshot, and the body does not claim a live reprice during checkout.

The port comment says “price policy.” The query is `offers` / `offer_products` / `products.base_price`. It does not select `channel_price_policies` and does not invent a bridge from `/user/promos`.

`BLACKSTORE_INTEGRATION` is untouched. Existing V7 still refuses to leave that module anything but `DISABLED`. This PR does not enable it, does not add a live companion, and does not exercise `PRICE_OVERRIDE`.
