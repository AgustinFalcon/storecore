## Catalog badge

`catalogOffersBadge` is `offersOnly && isApiOfferVisible`. `CatalogPageViewComponent.offersBadge` passes `state.query.offersOnly`, the product bounds, and `new Date()`. The grid binds `[offer]="offersBadge(product)"`.

`isApiOfferVisible` is true when either bound is missing or blank. `Sólo ofertas` therefore paints `Oferta` when the API sends no window, which is the badge the prior note said the grid had dropped. With the filter off, that helper is false, and the tile still paints `Oferta` from `product.offerRef` when the API sent one.

A closed window (`until <= from`, or `now` outside `[validFrom, validUntil)`) makes `catalogOffersBadge` false. `CatalogStore.search` maps with `withoutClosedOfferBadge` and does not filter the row out. That helper clears `offerRef` and leaves the price reference. The tile rule is `offer || product.offerRef`, so the closed row stays on the grid, keeps the API effective price, and does not paint `Oferta`. `loadProduct` uses the same helper. Product detail still badges from `product.offerRef`, so a closed window shows “sin oferta” and `price.effective` is the mapped API value.

The home rail is unchanged as a template: `[offer]="true"`. `CatalogStore` still lists a home card only when `isApiOfferVisible` is true. A missing window stays on the rail and paints `Oferta`. A closed window is omitted from the rail, so that forced badge does not paint it. The catalog grid and the product page keep the product.
