## Implementation

`/catalog` reads and writes `q`, `brand`, `category`, and `offers=1`.

| Behavior | Result |
| --- | --- |
| Read | `catalogQueryFromParams` trims `q`, `brand`, and `category`. `offersOnly` is true only when `params.get('offers') === '1'`. `offers=true` stays false. |
| Write | `catalogQueryParams` omits empty fields with `null` and writes `offers: '1'` only when `offersOnly` is true. `search()` passes that map to `Router.navigate` on the current route, which replaces the query string. |
| Route already open | `ngOnInit` subscribes to `queryParamMap` and `applyRouteQuery` replaces the toolbar and calls `store.search()` on every emission, including a later home/header link. `ngOnDestroy` unsubscribes. `loadFacets()` still runs once. |
| Buscar / Reintentar | Both emit `searchSubmit`. If the normalized toolbar already matches the URL, `search()` calls `store.search()` and does not navigate, so a repeat does not depend on a second param emission. If it differs, `search()` only navigates; the subscription performs the single fetch. |
| API flag | Unchanged repository: `offersOnly` still sets the HTTP param `offers=true`. The page query string stays `offers=1`. |
| Checkbox | The offers `ngModel` inside the toolbar `<form>` now has `name="offers"`. The other controls already had names. Submit still `preventDefault()`s and emits; the URL is not a native form GET. |
| Header search | `ShellComponent.search` still navigates to `/catalog` with `{ q }` or `{}`. An already-mounted catalog page applies that emission and drops brand, category, and offers. |

Container spec: entry `?offers=1&category=luz` loads facets once, sets that query, and searches once; a reused `?q=foco` clears brand, category, and offers and searches again. A toolbar write navigates with `{ q, brand, category: null, offers: null }` without a second `store.search()`; once the map matches, Buscar searches again and does not navigate.

Domain spec: offers-only link keeps `category` and `offers=1` and drops blank `q` / `brand`; a non-offers search writes `q` and `brand` and clears `offers`; `offers=true` does not enable the flag; trim round-trips.
