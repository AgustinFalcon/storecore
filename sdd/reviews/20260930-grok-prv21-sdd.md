## Findings

### P0 — blocking before merge

| ID | Item | Detail |
| --- | --- | --- |
| P0-01 | **DENIED override audits roll back with failed Tx-B** | `authorizeOverride` calls `auditOverride` then throws (`VALIDATION`, `BlackStoreForbidden`) or returns false inside `tx.execute`. Proposal §44 requires DENIED audit in **its own** committed transaction before 400/403/422. Current behavior loses DENIED rows and violates fail-closed audit. |
| P0-02 | **PENDING not deleted on override validation 400** | Invalid `X-Override-Reason` (length) or invalid `X-Actor-Role` throws `VALIDATION` without `deleteClaim`. Proposal §44/§54: 400 on Tx-B invalid shape must DELETE PENDING. |
| P0-03 | **Audit payload contract wrong/incomplete** | `auditOverride` JSON uses `declaredRole` = `principal.serviceRole.wire` (always `SERVICE`) instead of optional `X-Actor-Role`; `catalogRequested` = `operationId` instead of requested catalog version; omits redacted override reason and requested/live price versions per line. |
| P0-04 | **Missing `PRICE_OVERRIDE` companion guard** | Override checks credential scope in Kotlin only. `pos_companion_effect_guard(..., 'PRICE_OVERRIDE')` (V10) is the canonical path for scope **and** module ACTIVE/kill-switch. Without it, capability-disabled module could diverge from guard semantics if scopes were ever stale on principal. |
| P0-05 | **No catalog snapshot/cursor evidence on override ALLOW** | When `catalogStale`, proposal §44 requires requested `catalogVersion` to exist in durable cursor/snapshot issued to the companion (in addition to owned quotes). Code only verifies `blackstore_price_quotes`, allowing arbitrary stale catalog strings when quotes match. |
