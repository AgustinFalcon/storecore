## Honesty — transaction wiring (observed, not fail)

SDD prose in `plan.md`, `convergence.md`, and `tasks.json` cites `@Transactional(readOnly = true, isolation = REPEATABLE_READ)` on the Spring proxy. **Observed implementation (pre-existing, not modified in this slice):** `JdbcBlackStoreSagaEngine` wires a dedicated `TransactionTemplate` bean field `readTx` with `ISOLATION_REPEATABLE_READ` and `isReadOnly = true`; HTTP adapter/service layers do **not** carry `@Transactional`. Adding `@Transactional` here would be a forbidden production change for PIC-006A.

This review treats that as **documented field observation**, not a P0: the slice doc (`posc006-implementation-slices.md`) already records `TransactionTemplate` ownership; the test asserts the wired `readTx` flags and proves zero domain writes via HTTP snapshots. No evidence that GET/reconcile escape read-only at the JDBC layer within the photographed tables.
