## Implementation against the SDD why

`InventoryEventType`, `InventoryChannel`, and `ReservationStatus` are sealed classes with nested `data object` cases and a single `fromWire` that trims. Known wires are the V6 ledger set (`RESERVATION`, `RELEASE`, `SALE`, `REFUND`, `RETURN_RECEIVED`, `ADJUSTMENT`, `RECONCILIATION`, `STOCK_COMMIT_EXTERNAL`), the V6 channels (`WEB`, `MERCADO_LIBRE`, `INTERNAL`, `EXTERNAL_BLACKSTORE`), and the V1 reservation statuses. Null, blank, and any other text, including `SALE_OK`, `POS`, and `HELD`, map to the `Unknown` singleton. Each `Unknown.wire` is the constant `unknown`. The raw value is not stored on the type and is not returned as `wire`.

`InventoryLedgerPairing.allowed` matches the four arms of `ck_inventory_ledger_event_channel_pairing`: `SALE` only with `WEB` or `MERCADO_LIBRE`; `STOCK_COMMIT_EXTERNAL` only with `EXTERNAL_BLACKSTORE`; `RESERVATION` and `RELEASE` with all four known channels; `REFUND`, `RETURN_RECEIVED`, `ADJUSTMENT`, and `RECONCILIATION` with `WEB`, `MERCADO_LIBRE`, or `INTERNAL`. `Unknown` event is not allowed. An `Unknown` channel fails every `is` check, so it is not allowed either.

Writers persist `.wire` of known cases only:

- `JdbcInventoryService` reserve / consume / release / expiry / adjustment / Mercado Libre sale use `Reservation`+`Web`, `Sale`+`Web`, `Release`+`Web`, `Adjustment`+`Internal`, `Sale`+`MercadoLibre`, and reservation statuses `Active`, `Consumed`, `Released`, `Expired`. Reads go through `ReservationStatus.fromWire`. `Unknown` is not `Active` and is not `Consumed`, so those rows are skipped.
- `JdbcBlackStoreSagaEngine.appendLedger` takes `InventoryEventType` and always writes `InventoryChannel.ExternalCompanion.wire`. Call sites pass `Reservation`, `StockCommitExternal`, and `Release`, which the V6 pairing allows on `EXTERNAL_BLACKSTORE`. Reservation updates use `Active`, `Consumed`, `Released`, and `Expired`.

Those pairs are legal under the existing CHECK. `Unknown.wire` (`unknown`) is outside both CHECKs, so a mistaken persist would fail closed in Postgres rather than store the caller’s raw text. Companion saga `state` strings (`COMMITTED`, `RELEASED`, `EXPIRED`) are the operation row, not `inventory_reservations.status`. Refund, return, and reconciliation stay in the closed set because V6 lists them; this diff does not add writers for them.

`InventoryLedgerTypesTest` checks known wires, `Unknown` identity, fixed wire `unknown` for a bad event and a bad channel, and the distinctive V6 pairing rows (including `Unknown` event rejected).
