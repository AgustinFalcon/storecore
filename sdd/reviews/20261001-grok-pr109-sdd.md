## Implementation review

`FulfillmentNextAction` no longer switches on raw strings. The string overloads trim through `fromWire` and return `transition?.wire`. `PAID_STOCK_REVIEW` still suppresses both hints. A missing RMA (`null` or blank after trim) still suggests `RECEIVED`. That keeps the hint on the read model.

Stored wires that previously had a hint still do:

| Stored wire | Next hint |
| --- | --- |
| shipment `PENDING` / `PREPARING` / `SHIPPED` | `PACKED` / `SHIPPED` / `DELIVERED` |
| shipment `DELIVERED`, `CANCELLED`, anything else | null |
| RMA absent | `RECEIVED` |
| RMA `RETURN_RECEIVED` / `INSPECTED` | `INSPECTED` / `ADJUSTED` |
| RMA `REQUESTED`, `APPROVED`, `REJECTED`, `CLOSED`, anything else | null |

`Unknown` uses the fixed wire `unknown` and does not echo the rejected raw text. Order `CANCELLED` / `EXPIRED` / `REFUNDED` still do not suppress a shipment hint. That matches the previous string `when` (only `PAID_STOCK_REVIEW` short-circuited).

## Required change

Kotlin closed states in this repo are `sealed class` or `enum` (`CatalogVersion`, `CapabilityAdminOperation`, `CatalogCursorFormat`). The workspace rule reserves the private-constructor class for TypeScript, where `sealed` does not exist.

`OrderStatus`, `ShipmentStatus`, `ShipmentTransition`, `RmaStatus`, and `RmaTransition` are open classes with a private constructor and companion singletons. `fromWire` plus `Unknown` is present, and the constructor is private, so callers cannot invent instances. A `when` on these types is still not exhaustive, which is the point of a Kotlin sealed type.

Restate each set as a `sealed class` (or `enum class`) with one `fromWire` and one `Unknown` case. Keep the same hint wires, the null next action for cancelled and unknown stored states, and the read-model boundary. Do not add Flyway, companion HTTP, or live Mercado Libre / Mercado Pago.
