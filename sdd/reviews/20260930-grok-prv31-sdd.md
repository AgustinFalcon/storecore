## Round-1 P1 — re-judged

P1 asked for a PG16 test that seeds an external ML listing and an active product with stock, installs a delivery-insert failure trigger, calls `saveProduct` with a change that would emit, and asserts the exception plus zero partial catalog, outbox, projection, and balance mutation.

`saveProductDeliveryFailureRollsBackCatalogBalanceAndOutbox` does that:

1. Seeds `SKU-DSP005-RB` with available 6, reserved 0, safety 1, external account, listing `MLA-005-RB`.
2. Activates the listing first. Desired quantity is `max(0, 6-1) = 5` and `stockOutbox` is 1. That baseline is the pre-image.
3. Installs `BEFORE INSERT` on `public.channel_outbox_delivery` that `RAISE EXCEPTION 'DSP005_DELIVERY_FAIL'` when the parent `channel_outbox.kind` is `STOCK_DESIRED_CHANGED`.
4. Calls `catalog.saveProduct` with name `RolledBack`, `availableQuantity` 3, `active = true` (eligible emit: desired would become 2).
5. Asserts the exception text contains `DSP005_DELIVERY_FAIL` (message or direct cause), product name still `SKU-DSP005-RB`, `available_quantity` still 6, outbox count still 1, `desired_quantity` still 5. Trigger is dropped in `finally`.

Why this is the saveProduct transaction, not a separate one:

- `JdbcCatalogService.saveProduct` runs the product/variant updates, `inventory.setAvailableQuantity`, and `inventory.reproject` inside one `TransactionTemplate.execute`.
- The quantity change emits inside `setAvailableQuantity` → `projectIfEligible` → `outbox.appendDesiredStockChanged`, which inserts `channel_outbox`, the stock-projection line, then `channel_outbox_delivery` in that same JDBC callback. The trigger sees the outbox row (same transaction) and aborts before the callback returns.
- `PlatformTransactions` builds `TransactionTemplate(manager)` with default `PROPAGATION_REQUIRED`. The test uses the same default on one `DataSourceTransactionManager`. Nested `execute` joins the outer transaction; the inner callback throws before commit, so the product update cannot commit apart from the balance, snapshot, and outbox.
- `reproject` is not reached on this path. The failing delivery is the one `saveProduct` already asked for via `setAvailableQuantity`. Staying at desired 5 (not 2) and outbox 1 (not 2) is the rolled-back snapshot and outbox, not an unchanged no-op: a successful emit would have changed both, and a trigger that did not fire would not have produced `DSP005_DELIVERY_FAIL`.

P1 is closed on the working tree.
